# Bring up The Price Is Live

1. Use Node 22 or newer. In the repository, run `npm install --no-audit --no-fund`. Keep keys and real phone numbers out of the repository, screenshots, and shared logs. This runs as one process, with no web server.

2. Create the accounts. Follow [Chert's setup instructions](https://app.trychert.com/skills.md) to obtain a ready FaceTime line, API key, project ID, and line ID. Ask Chert to enable outbound group calls and confirm group video and caller capture. Create a LiveKit project and copy its WebSocket URL, API key, and secret from the same project. Create an ElevenLabs API key and select a voice ID that your account can use for host speech and Scribe realtime access. Create a Gemini key in Google AI Studio. Create an Atlas M0 cluster, a database user, and a connection URI; allow this machine's IP in Atlas network access. Do not leave unrestricted network access enabled after the event.

3. Run `cp .env.example .env.local`, then fill the blank entries locally. Replace the LiveKit URL placeholder. Set the Chert IDs and key; keep `CALL_MODE=outbound_group` and the example API bases unless Chert confirms otherwise. Set `ELEVENLABS_API_KEY`, `ELEVENLABS_VOICE_ID`, `GEMINI_API_KEY`, and `MONGODB_URI`. Generate a private random `PHONE_HASH_SALT`, for example with `node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"`, and paste it into the local file. Set the real line display number only in that file. Keep the example model, format, stage, and budget settings for the first test; their availability still needs checking. The loader reads `.env.local`. Never commit it.

4. Verify all four player phones through the Chert dashboard: each phone texts its six-digit verification code to the line. One unverified recipient rejects the entire group. Verify a judge's phone before the demo, or lend them an already verified team iPhone. Each player must also text the line first to open the trial's 24-hour reply window; verification alone does not replace joining the game.

5. Run `npm run doctor`. Each environment setting is reported as `OK …: set` or `MISSING …: missing`; values are never printed. Defaulted settings can still show missing because this checks explicit configuration. Missing entries are warnings; `npm run doctor -- --strict` also fails for missing entries. `npm run doctor -- --offline` checks configuration without service probes. Online probes mint a LiveKit token locally, GET Chert lines, read ElevenLabs characters left, send a one-token Gemini request, and ping MongoDB. Each probe has a five-second limit; `FAIL` gives exit 1. A green token check does not prove LiveKit connectivity, and a green lines endpoint does not prove the line is ready or group-enabled. Confirm these in the dashboard and a real call. Gemini probing uses a small amount of quota.

6. Run `npm run check`, then `npm start`. Keep that terminal open. Runtime logs belong in the process terminal; for a local capture use `npm start > /tmp/price-is-live.log 2>&1` and inspect that file locally. Review logs before sharing; never paste credentials, full phone numbers, tokens, or camera frames. Stop with Ctrl-C and restart with `npm start` after changing the local env. Only one agent should use the line at once. This runbook uses outbound Plan B; an inbound `chert dev` session is a separately verified setup, not required for this flow.

7. Have two to four players text `I'm in, I'm {name}` to the line, replacing `{name}` with their name. The first player is the main player and texts `start`. Answer the outbound FaceTime **Video** call on every phone. For the short rehearsal, the main player texts `demo` in the lobby before starting; this selects the two-item demo intended for about two minutes. Alternatively set `DEMO=1` before boot. Each owner privately texts their item name and size to the line; everyone else guesses when their podium is active. Closest without going over wins. Read the captions, reveal, and scoreboards; results are also sent by text. Text `REMATCH` during the finale rematch window to request a new outbound call, subject to remaining trial minutes.

8. If audio is silent, keep playing from captions and text your numeric guess during your own turn. After two silent guess windows, the game uses **TEXT MODE** and longer text windows. Check the output device, FaceTime microphone permissions, ElevenLabs quota, and whether the host and stage publish from the same LiveKit participant with exactly one audio track. Chert can end a silent bridge after about ten seconds, so an immediate disconnect also needs a line/audio check. Missing caller camera is handled by item texts; never depend on a camera tile for a demo.

9. Budget the trial: the spec records five minutes per call and 50 FaceTime minutes total, with one active call per line. Confirm the actual remaining allowance and expiry in Chert; the spec records 24 hours normally and 48 hours for eligible event trials. The normal game targets a finale by 4:30. A rematch spends another call's minutes. Keep rehearsals short and record date, duration, remaining minutes, result, and faults in `docs/call-log.md` (create it locally if absent). Do not put phone numbers or keys in the call log. Save minutes for judging.

10. **TO VERIFY ON THE REAL LINE** — work through every unresolved item from SPEC §0 and §3 before promising a feature. Record observed behavior, with secrets removed, in `docs/verified.md`:
    - Outbound groups enabled; group video works. Inbound groups with “add person” remain unverified; FaceTime link joining requires separate enablement. Keep outbound Plan B until those are proven.
    - All recipients verified, including judges; reply-only messages work after each player's join text. Caller names and speaker IDs are not dependable; use join texts and turn order.
    - Caller capture enabled for this line; whether the group composite includes the owner's tile, all tiles, UI chrome, names, or self-preview. Check fresh frames and muted/missing cameras; keep text items as the main path.
    - Host audio and stage video arrive from the same participant, one audio publisher only; audio is audible in both directions after `bridge_ready`, without the reported silent-audio problem or early disconnect. Confirm actual start/bridge events and holding-screen timing.
    - Calls use the facetime API host and messages use the app host; resolve the documented host mismatch with Chert before changing local bases. Confirm outbound readiness, token acceptance, permissions, expiry, and line ownership.
    - Actual shared-message field names, timestamps, sender handles, and inbound direction match the poller. Inspect a redacted sample, never log a raw message with a real phone. Shared-line `message.received` webhooks, streaming, and image attachments remain unverified; this game uses text polling.
    - Confirm installed Chert CLI/starter compatibility if trying the separate inbound path, and that video subscription is enabled if capture is used. Check line-specific group capacity, busy behavior, contact/message limits, trial expiry and remaining allowance; published limits are not a capacity test.
    - Confirm the actual Devpost deadline with organizers; SPEC §0's reported deadline is unconfirmed. Confirm current sponsor rules, public repository/license requirements, free-tier privacy terms, and the optional A-Team decision before submission.
    Also verify this build's ElevenLabs voice/PCM format, Scribe events and permissions, Gemini model access, Atlas ping and writes, and stage framing on a real iPhone. These require real services and cannot be established by offline tests.

11. After submission, stop the process and any Chert dev session, end active calls, and rotate Chert, LiveKit, ElevenLabs, Gemini, and Atlas credentials. Update only the private local env, then rerun doctor. Revoke old keys, remove temporary Atlas network rules, and delete private log captures. Keep the phone hash salt private; rotating it changes player identity hashes, so plan any retained-data migration first. Rotate immediately if a key was exposed.
